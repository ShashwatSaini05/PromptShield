# PromptShield-ML

Machine learning component of **PromptShield**: a text classifier that labels
a user prompt as `SAFE` or `PROMPT_INJECTION`.

This repo contains **only** the ML piece — dataset, training pipeline, saved
model, and a standalone CLI predictor. No web app, API, database, auth, or
LLM integration is included; those are out of scope for this stage.

## Dataset

**The dataset is entirely synthetic**, generated by `generate_dataset.py`
from hand-written templates and slot-fillers (topics, phrasing variants,
politeness/urgency prefixes and suffixes). No real user data, scraped
conversations, or third-party dataset was used. Every prompt is
programmatically assembled, then deduplicated — nothing is produced by
copy-pasting a single canonical sentence.

- 3,920 total prompts, perfectly balanced: 1,960 `SAFE` / 1,960
  `PROMPT_INJECTION`.
- `SAFE` prompts span many domains: programming, ML/CS concepts, general
  knowledge, writing help, and everyday questions — including some that
  mention words like "instructions" or "system" in an innocuous, technical
  sense (e.g. "What's the standard operating procedure for a fire drill?"),
  so the model isn't just learning "any mention of instructions = attack."
- `PROMPT_INJECTION` prompts cover five attack sub-categories: instruction
  override, system-prompt extraction, role manipulation/jailbreak, context
  manipulation, delimiter/fake-system-tag injection, and indirect
  social-engineering framing — each expressed with multiple templates,
  determiners, and politeness/urgency variations rather than one fixed
  phrase.

Re-run `python generate_dataset.py` to regenerate the CSV (deterministic,
seeded with `random.seed(42)`).

## Pipeline (`train.py`)

1. **EDA** — sample counts, class balance, missing/duplicate checks, prompt
   length statistics (characters and words) by class, class-distribution
   plot, length-distribution plot.
2. **Cleaning** — drop nulls, drop exact duplicates, normalize whitespace.
   Deliberately does **not** strip punctuation or remove stopwords, since
   casing/punctuation patterns ("###", ALL CAPS) and function words
   ("ignore", "no") carry real signal for this task. Rationale for every
   decision is printed by the script.
3. **Split** — 80/20 train/test, `stratify=y`, `random_state=42`.
4. **Features** — `TfidfVectorizer(ngram_range=(1,2), min_df=2, max_df=0.9,
   sublinear_tf=True)`. Bigrams capture short directive phrases ("ignore
   previous", "system prompt") as single features.
5. **Baselines** — Logistic Regression, Multinomial Naive Bayes, Linear SVM,
   compared on Accuracy/Precision/Recall/F1 on the same split.
6. **Model selection** — ranked by **Recall → F1 → Precision → Accuracy**.
   For a security detector, a false negative (real attack labeled `SAFE`)
   is far more costly than a false positive (benign prompt flagged), so
   recall is prioritized first.
7. **Tuning** — `GridSearchCV` (5-fold stratified CV, scored on recall),
   fit only on the training fold — the test set is never touched during
   tuning.
8. **Final evaluation** — metrics, confusion matrix (with plot), full
   classification report, all computed once on the untouched test set.
9. **Confidence** — `predict_prompt(text)` returns `(label, confidence)`
   using the model's actual `predict_proba` output.
10. **Unseen-prompt test** — a small hand-written set of prompts not present
    anywhere in the training data, to sanity-check generalization.
11. **Error analysis** — lists actual false positives/negatives from the
    test set and discusses likely causes.
12. **Feature analysis** — top TF-IDF n-grams by learned coefficient for
    each class.

## Results (actual, from the last training run)

All baseline models were evaluated on the identical held-out test set
(784 prompts):

| Model               | Accuracy | Precision | Recall | F1     |
|----------------------|---------:|----------:|-------:|-------:|
| Logistic Regression  | 99.87%   | 99.75%    | 100.0% | 99.87% |
| Linear SVM            | 99.87%   | 99.75%    | 100.0% | 99.87% |
| Naive Bayes           | 99.74%   | 99.49%    | 100.0% | 99.75% |

**Selected model: Logistic Regression** (tuned via GridSearchCV,
best params `C=1`, `class_weight=None`, CV recall 1.0000).

**Final test-set performance:** Accuracy 99.87%, Precision 99.75%,
Recall 100.0%, F1 99.87%. Confusion matrix: 1 false positive, 0 false
negatives, out of 784 test prompts.

**Important caveat on these numbers:** this dataset is synthetic and
template-generated, so the two classes are more lexically separable than
real-world traffic would be — a human red-teamer or a novel attack style
not resembling these templates would likely score lower. Treat these
metrics as a validation that the pipeline works correctly, not as a
production-readiness guarantee. See "Security Limitations" below.

## Using the saved model

```bash
pip install -r requirements.txt
python train.py      # regenerate model/*.pkl (optional, already included)
python predict.py    # interactive CLI using the saved model
```

`predict.py` loads `model/prompt_injection_model.pkl` and
`model/tfidf_vectorizer.pkl` directly — it does not retrain anything.

## Security limitation (read this)

> This model is a statistical text classifier and cannot guarantee that a
> prompt is safe. Prompt injection techniques can evolve, and unseen attack
> patterns may bypass the classifier.

- False positives are possible (legitimate prompts flagged as attacks).
- False negatives are possible (real attacks classified as safe).
- Performance may differ on prompts outside the training distribution —
  different languages, encoding/obfuscation tricks, or attack phrasing
  that shares little vocabulary with these templates.
- Dataset quality strongly affects performance; this dataset is synthetic,
  so real-world adversarial prompts may look different from what the model
  has seen.

This classifier is intended as **one layer of defense** (e.g. flagging
prompts for review or adding friction before they reach a downstream LLM),
not as a sole safeguard against prompt injection.
